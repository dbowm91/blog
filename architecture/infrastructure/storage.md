# Storage (`app/storage.py`)

Storage abstraction for media files.

## Backends

| Backend | Environment | Purpose |
|---------|-------------|---------|
| Local | `STORAGE_BACKEND=local` (default) | Filesystem storage |
| S3 | `STORAGE_BACKEND=s3` | S3-compatible object storage |

## Local Storage

```python
class LocalStorageBackend(StorageBackend):
    def __init__(self, base_dir: str): ...

    def save(self, filename: str, data: bytes) -> str: ...
    def load(self, filename: str) -> Optional[bytes]: ...
    def delete(self, filename: str) -> bool: ...
    def exists(self, filename: str) -> bool: ...
    def url(self, filename: str) -> str: ...  # Returns /static/uploads/{filename}
    def list_files(self, prefix: str = "") -> list[str]: ...
    def path(self, filename: str) -> str: ...  # Local filesystem path
```

## S3 Storage

```python
class S3StorageBackend(StorageBackend):
    def __init__(
        self,
        bucket: str,
        region: str = "us-east-1",
        endpoint: str = "",
        access_key: str = "",
        secret_key: str = "",
        public_url: str = "",
    ): ...

    def save(self, filename: str, data: bytes) -> str: ...
    def load(self, filename: str) -> Optional[bytes]: ...
    def delete(self, filename: str) -> bool: ...
    def exists(self, filename: str) -> bool: ...
    def url(self, filename: str) -> str: ...  # Returns public URL
    def list_files(self, prefix: str = "") -> list[str]: ...
```

**Error Handling Limitation:** `exists()` returns `False` and `list_files()` returns an empty list on any error (network issues, authentication failures, bucket not found, etc.). Callers cannot distinguish between "file does not exist" and "error checking existence" from the return value alone.

## Environment Variables

| Variable | Description |
|----------|-------------|
| `STORAGE_BACKEND` | `local` or `s3` |
| `S3_BUCKET` | S3 bucket name |
| `S3_REGION` | AWS region (default: us-east-1) |
| `S3_ENDPOINT` | S3-compatible endpoint (for MinIO, etc.) |
| `S3_ACCESS_KEY` | AWS access key |
| `S3_SECRET_KEY` | AWS secret key |
| `S3_PUBLIC_URL` | Custom CDN URL |

### The `[storage]` Section of `config.toml`

`[storage]` in `config.toml` is **not** inert. `_storage_settings()` in `app/storage.py`
starts from the environment snapshot taken at import time and then, when an application
context is active, overrides each field with the typed configuration from
`current_app.config["DEVLOG_CONFIG"].storage`. The typed configuration therefore wins over
the environment; the environment remains the fallback for callers outside an app context.

## Module-Level Functions

### `init_storage()`

```python
def init_storage(base_dir: str) -> StorageBackend:
```

Initializes the global storage singleton with a `LocalStorageBackend` using the given `base_dir`. Used during app startup to configure the upload directory.

### `storage_delete_file()`

```python
def storage_delete_file(filename: str) -> bool:
```

Convenience function to delete a file from the configured storage backend. Returns `True` on success, `False` on failure. Delegates to `get_storage().delete(filename)`.

## Factory Function

```python
def get_storage_backend() -> StorageBackend:

    return LocalStorageBackend(...)

    """Returns singleton storage instance."""
```

## Image Processing

### `upload_with_processing()`

```python
def upload_with_processing(
    filename: str,
    file_content: bytes,
    generate_variants: bool = True
) -> tuple[str, None] | tuple[None, str]:
```

Saves image and queues `generate_image_variants` Celery task.

### Variant Cleanup on Replacement

When uploading a new image with the same filename, old variants are automatically cleaned up before creating new ones:
- Width prefixes: `400_`, `800_`, `1200_`
- Format suffixes: `.webp`, `.avif`

The cleanup uses prefix matching to find and delete any existing variants for the base filename.

### Responsive Variants

Generated by Celery task (`generate_image_variants`):
- `400_{basename}.webp`
- `800_{basename}.webp`
- `1200_{basename}.webp`
- Original format variants

### S3 Variant Generation Flow

When `STORAGE_BACKEND=s3`:
1. `upload_with_processing()` saves original file to S3
2. Celery task `generate_image_variants()` retrieves file from S3
3. Task generates all responsive variants locally
4. Variants are uploaded back to S3 under same key prefix
5. Local temp files are cleaned up after upload

This differs from local storage where files remain on filesystem throughout processing.
